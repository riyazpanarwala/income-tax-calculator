# PortFin JSON integration

PortFin supplies realized FIFO lots. The calculator alone determines final tax. No engine, database schema or public API was changed.

## Version 1 contract

The canonical synthetic fixture is `tests/fixtures/portfin-v1.json`, generated by PortFin's `buildIncomeTaxExport`. Root fields are strictly allowlisted:

- `schemaVersion: 1`, `source: "portfin"`, `financialYear: "YYYY-YY"`, UTC `generatedAt`.
- `summary`: `section111A`, `section112A`, `otherSTCG`, `otherLTCG`, `review`; each has non-negative `gain` and absolute `loss`, before set-off or the annual 112A exemption.
- `gains`: one row per matched FIFO lot, with export-local `id` and `transaction`, `kind`, `asset`, `confirmed`, `reason`, instrument `symbol/name/isin/exchange`, acquisition and sale dates, quantity, proceeds, cost, signed gain, holding days and `source: "fifo"`.
- `warnings`: completeness warnings that block an estimate.
- `reconciliation`: matched sale count, lot count, review/loss lot count and signed total gain.

No tax liability, credentials, account IDs or Prisma objects are exported. Money is rounded to paise per lot; reconciliation uses those exported amounts. Lots may include `transferExpenditure`, a non-negative amount rounded to paise; older v1 exports omit it and are treated as zero. Validation reconciles proceeds minus cost minus transfer expenditure to the exported gain, allowing one paisa for independent rounding. The exported gain is imported without deducting expenses again. Quantities retain FIFO precision.

## Mapping and review

| Export kind | TaxInput mapping                                                     |
| ----------- | -------------------------------------------------------------------- |
| `111A`      | `kind: '111A', asset: 'equity'`                                      |
| `112A`      | `kind: '112A', asset: 'equity'`                                      |
| `otherSTCG` | `kind: 'otherSTCG'`, ordinary-rate gain                              |
| `112`       | `kind: '112'`, verified general LTCG; displayed in otherLTCG summary |
| `otherLTCG` | Recognized but unsupported; review, no partial estimate              |
| `review`    | No invented Gain category; retain external row for review            |

For supported rows, `amount` is the signed FIFO gain; dates, asset and confirmation are retained. No proceeds are substituted for gain. Current-year eligible 111A/112A equity losses are imported alongside gains, and the engine applies LTCL against LTCG, then STCL against STCG and remaining LTCG before the annual 112A band. Losses never reduce other income. Residual losses are reported; brought-forward claims and carry-forward eligibility remain outside scope. Negative rows under other provisions and mixed-provision loss allocation require review.

The adapter returns a guarded TaxInput using existing unsupported flags. The UI stores import review separately, preserving the user's own unsupported-circumstance selections; unchecking a checkbox cannot make an incomplete import produce a tax estimate. Replace with reconciled data or discard the import. Discard restores pre-import capital gains, preserving current income/payment fields and user-selected scope flags. Session metadata is held in React memory, survives panel/tab changes, and clears on reset/reload.

The complete LTCG/STCG reconciliation includes every source lot, including older lots marked with PortFin's explicit grandfathering review reason. Unrelated review records stay unclassified. These reporting totals are not substituted for verified taxable gains.

For uploaded and pasted JSON, an exact mutual-fund ISIN match in the bundled [official AMFI 31 January 2018 reference](https://www.amfiindia.com/uploads/NAV_All_31_Jan2018_cf117d62c0.txt) automatically supplies the NAV, calculates the grandfathered cost and records the source. Only `AMFI` instruments with PortFin's precise grandfathering-only reason qualify: in the exporter this reason follows its equity/STT checks. The importer does not convert unresolved STT/category warnings or exchange-listed shares/ETFs into eligible funds. Different dates, invalid NAVs, missing ISINs and conflicting reference entries remain unresolved. Exact ISIN matching distinguishes Regular/Direct and Growth/IDCW plans across scheme renames. The dated text is served from the app's own `data/` directory, so GitHub Pages does not need cross-origin AMFI requests and no portfolio data is sent externally. A failed asset load offers retry and the existing manual fields.

The automatic adjustment uses the exported quantity and matching historical ISIN's unit basis. For unmatched lots, **Verify older equity / fund acquisition costs** accepts FMV per unit, a source reference and explicit eligibility/unit-basis confirmation. Either route recalculates the summaries and preserves original cost, total FMV, proceeds, expenses and source in an optional `grandfathering` object. The original report remains in the in-memory session, separately from adjusted tax amounts. No personal source file is overwritten. Re-upload the original to repeat the automatic lookup or change manual FMV assumptions.

When an estimate is withheld, the panel identifies remaining source or lot-review issues. **View PortFin import details** opens Capital gains and scrolls to the retained import. Both preview and accepted import show excluded lots with signed amounts, dates, categories and reasons. The confirmation button says **Import for review — estimate withheld** while blockers remain. Discard restores the previous gains; it does not calculate the discarded export. Instrument eligibility is never inferred from NSE/BSE or a stock symbol.

## Replacement and duplicate policy

Replace is the default and requires an explicit preview confirmation. It updates capital gains and necessary review flags only. A canonical serialized fingerprint of the FY, lots and warnings detects repeat exports independently of generation time. Reconfirming an identical import preserves current gains, including manual edits/removals. Without metadata, default replacement is still idempotent.

The first import can explicitly merge after reviewing broker/manual overlap. Exact Gain matches are matched as a multiset and retained rather than duplicated. This cannot identify overlap with aggregated broker totals: the warning and explicit user decision are essential. Once a PortFin import exists, a changed export must replace gains; incremental merging is intentionally unavailable. Switching back to broker mode asks before replacing current gains.

## Existing limitations preserved

- Only FY 2026-27 has calculator rules. FY 2025-26 is rejected, not silently translated or enabled.
- At most 100 accepted Gain rows, matching existing engine validation; larger imports are rejected without truncation.
- PortFin stores STOCK/MF and exchange, not STT or equity-oriented-fund eligibility. Users must explicitly attest classifications in its export preview; default is review.
- Generic PortFin holding periods use 365 days. Calendar-anniversary disagreements require review without changing PortFin's Tax tab numbers.
- PortFin groups FIFO by symbol and loads the first portfolio. There is no broker/account-aware lot identity. Do not treat this as an account-reconciled consolidated ledger.
- Corporate actions modify historical quantity/price in place, without an action ledger. The adapter preserves the resulting FIFO amounts; it cannot independently verify bonus/grandfathering treatment.
- Current PortFin exports can supply adjusted tax cost and separately itemised transfer expenditure. Older exports do not itemise transfer expenditure. Verify allowable costs before confirming tax eligibility; the importer checks arithmetic, not expense deductibility.
- Missing purchases, potentially truncated trade loading (1,000 records), and unsupported cases block reliance on an estimate. The UI passes raw trades to the export adapter for sale-quantity reconciliation. Holdings alone cannot reveal completely dropped unmatched sales.
- Current-year equity-only loss set-off and verified grandfathering inputs are supported. Brought-forward losses, mixed-provision loss allocation, protected property indexation and existing surcharge allocation restrictions remain outside scope.
